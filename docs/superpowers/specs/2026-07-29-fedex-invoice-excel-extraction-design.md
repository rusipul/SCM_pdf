# FedEx 청구서 PDF → Excel 자동 추출 설계

## 배경 및 목적

매달 FedEx 청구서 PDF에서 건별 Total 금액을 마감 Excel 파일에 수기로 복사/붙여넣기 하고 있음 (6월 기준 29건). 이 반복 작업을 자동화하여 PDF를 드래그&드롭하면 필요한 정보만 담긴 Excel 파일이 자동 생성되도록 한다.

## 범위

- 입력: FedEx 청구서 PDF (1개 또는 여러 개 동시 지원)
- 출력: 입력 PDF와 동일한 이름의 `.xlsx` 파일, 건별로 **선적일자 / AWB번호 / Total 금액** 3개 컬럼
- 실행: PDF 파일을 배치 스크립트 위에 드래그&드롭
- 검증: 추출된 건별 Total 합계와 PDF 1페이지의 Grand Total 비교

새 마감 Excel 양식은 별도로 정해진 것이 없으므로, 이번 작업으로 새로 설계한다.

## PDF 구조 (확인됨)

`FEDEX인보이스.pdf` 샘플 기준 (총 12페이지):

- **1페이지**: 요약 (Summary by Payment Type) — `Total Number of Shipments` 건수, `Grand Total KRW <금액>` 포함
- **2페이지 이후**: `Details by Payment Type` — 건별 상세가 페이지당 2~3건씩 반복. 각 건은 아래 패턴의 텍스트 줄을 포함:
  - `선적일자 Ship Date MM/DD/YYYY 발송인Sender 수취인Recipient`
  - `AWB 번호 Air Waybill Number <13자리 숫자> ...`
  - `합계Total <금액>` (쉼표+소수점 2자리 형식)

pdfplumber로 텍스트 추출 시 한글 포함 정상적으로 UTF-8 텍스트가 나오는 것을 확인함 (터미널 표시가 깨지는 것은 콘솔 코드페이지 문제일 뿐, 실제 데이터는 정상).

**구현 중 실제 샘플 PDF로 확인된 점 (설계 당시 가정과 다름):** `합계Total` 줄은 항상 단독 줄이 아니다 — pdfplumber가 같은 세로 위치의 텍스트를 한 줄로 묶기 때문에, 일부 건에서는 `규격Dimension ...` 필드가 `합계Total <금액>`과 같은 줄에 합쳐져 나온다 (예: `규격Dimension 36x34x5cm 합계Total 41,710.00`). 따라서 `합계Total`을 줄의 시작으로 앵커링하면 이런 건이 누락된다 — 파서는 줄 어디에 있든 `합계Total <금액>` 패턴을 찾도록 구현했다 (앵커 없는 `search`).

## 접근 방식

**텍스트 패턴 매칭 방식**을 사용한다. pdfplumber로 각 페이지의 텍스트를 줄 단위로 추출하고, 정규식으로 `Ship Date`, `Air Waybill Number`, `합계Total` 줄을 찾아 건별로 순서대로 짝짓는다. 같은 계정에서 매달 동일한 청구서 템플릿이 나오므로 이 방식으로 충분히 안정적이며, 좌표 기반 테이블 추출보다 구현·유지보수가 단순하다.

## 구성 요소

### 1. `extract.py`
- 입력: PDF 파일 경로 (커맨드라인 인자, 여러 개 가능)
- 처리 (PDF별로):
  1. pdfplumber로 전체 페이지 텍스트 추출
  2. 1페이지에서 `Grand Total` 금액 파싱
  3. 2페이지부터 정규식으로 (선적일자, AWB번호, Total) 튜플을 순서대로 추출
  4. 추출된 Total 합계와 Grand Total 비교
  5. openpyxl로 Excel 생성: 헤더(선적일자/AWB번호/Total 금액) + 건별 행 + 합계 행
  6. 합계 불일치 시 콘솔 경고 출력 + 엑셀 마지막 행에 "⚠ 합계 불일치 (추출 합계: X / PDF Grand Total: Y)" 표시
- 출력 파일명: `<원본 PDF명>.xlsx`, 원본과 같은 폴더에 저장
- 처리 결과(성공 건수, 검증 결과)를 콘솔에 요약 출력

### 2. `변환.bat`
- PDF 파일(들)을 이 파일 위에 드래그&드롭하면 실행됨
- 전달받은 모든 인자를 `extract.py`에 그대로 넘겨 한 번에 처리
- 처리 후 `pause`로 콘솔 창을 유지하여 결과/오류 메시지를 확인할 수 있게 함

## 데이터 흐름

```
PDF 파일(들) 드래그
   → 변환.bat 실행 (인자로 PDF 경로 전달)
      → extract.py가 각 PDF에 대해:
           PDF 텍스트 추출 → 건별 데이터 파싱 → Grand Total 검증 → xlsx 저장
      → 콘솔에 파일별 결과(건수, 검증 통과/실패) 출력
```

## 에러 처리

- 예상 패턴(`Ship Date` / `Air Waybill Number` / `합계Total`)이 한 건도 발견되지 않으면 해당 PDF는 건너뛰고 콘솔에 오류 표시 (다른 PDF 처리는 계속 진행)
- 건별 항목 수가 맞지 않게 파싱되는 경우(예: 세 패턴 개수 불일치)는 해당 PDF에 대해 경고를 표시하고, 매칭 가능한 만큼만 처리
- Grand Total을 페이지 1에서 찾지 못하면 검증은 건너뛰고 그 사실을 콘솔에 표시 (추출 자체는 계속 진행)
- PDF가 아니거나 열 수 없는 파일이 드롭된 경우 해당 파일만 건너뛰고 나머지는 계속 처리

## 테스트 계획

- 제공된 `FEDEX인보이스.pdf` (29건, 12페이지)로 실행하여:
  - 추출된 건수가 29건인지 확인
  - 추출 합계가 PDF 1페이지 Grand Total(KRW 7,834,180.00)과 일치하는지 확인
  - 생성된 Excel의 값 몇 건을 PDF 원본과 육안 대조
- 여러 PDF 동시 드래그 시 각각 독립된 xlsx가 생성되는지 확인
- PDF가 아닌 파일을 섞어 드래그했을 때 나머지 PDF는 정상 처리되는지 확인

## 향후 확장 (지금은 범위 밖)

- 고정 마감 양식으로 값 채워넣기 (현재는 새 양식으로 생성)
- 누적 파일에 추가하는 방식 (현재는 PDF마다 새 파일)
- Freight/Deductions/Other Charges 등 상세 항목 추출
